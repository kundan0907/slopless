# Visual quality: judge the rendering

Use for the bounded visual check after building, or a detailed critique. Rules are tools for a decision, not a substitute for one.

## Five passes

1. **Hierarchy.** Squint. One element leads, the next supports it, the rest stays available. Long headings, equal-size card titles and muted evidence must not compete with the claim.
2. **Composition.** Alignment and spacing explain groups. Use scale and the subject's real material. Repeated grids need a reason. Removing borders without changing grouping is not a composition improvement.
3. **Reading.** Inspect the densest real content at the target display size. Chart labels, captions, errors and notes count. Check font loading, contrast, line breaks, clipping and overlays. A CSS font size before stage scaling is not its rendered size.
4. **Interaction and story.** The next action or beat is clear. The viewer keeps their place during transitions. Test keyboard focus, actual loading/error states and backward/rapid navigation where affected. Reduced motion must reveal the same information.
5. **Identity and fit.** Compare against the supplied brief, brand and explicit taste. Material, typography and imagery belong to this subject. A trend is allowed when chosen; do not replace one fashionable default with another.

## Completion

Record up to three concrete defects with view/state and evidence. Fix in one batch, then revisit the affected views. Critical unreadability, lost content, broken navigation or contrast cannot be waived because the patch budget is exhausted. Limit optional polish rather than hiding failures.

A scanner detects certain source patterns; it cannot establish visual quality, semantic content preservation or accessibility conformance. Do not treat 0 findings as approval. Scores are optional and require rendered evidence; explain the defect rather than inventing precision.

Sources: [NN/g visual-design principles](https://www.nngroup.com/articles/principles-visual-design/) inform scale, hierarchy and grouping; [progressive disclosure](https://www.nngroup.com/articles/progressive-disclosure/) informs keeping specialist controls secondary without hiding frequent tasks. These are design inputs, not a certification of the result.
